# Aino Acquisition Browser Worker V1.1

Self-hosted browser worker for the Aino Home Product Acquisition Engine. This version captures the structured AliExpress product response generated by `mtop.aliexpress.pdp.pc.query` and parses it before falling back to rendered-page observation.

## What it does

- Polls the deployed Aino Console for queued acquisition jobs.
- Opens AliExpress product pages with Playwright + Chromium.
- Captures the successful `mtop.aliexpress.pdp.pc.query` network response when available.
- Parses JSON/JSONP into product, SKU, price, stock, shipping, ship-from, and supplier-stated VAT/import evidence.
- Preserves the raw supplier response on the acquisition job for audit/debugging.
- Falls back to browser-visible page evidence if the structured response cannot be captured or parsed.
- Does not calculate Selection, Pricing, margin, dog-size suitability, or business decisions.
- Does not bypass CAPTCHA or anti-bot challenges.

## Requirements

- Node.js 20+
- A machine where Chromium can run
- Network access to the deployed Aino Console and AliExpress
- No paid scraping API is required

## Setup

```bash
cd worker
npm install
npx playwright install chromium
```

Set environment variables:

```text
AINO_CONSOLE_URL=https://your-aino-console.vercel.app
AINO_WORKER_TOKEN=<same secret configured in Vercel>
AINO_WORKER_POLL_MS=3000
AINO_ALIEXPRESS_API_WAIT_MS=15000
```

Then:

```bash
npm start
```

Keep the worker process running while acquisition jobs should be processed.

## Architecture

```text
Aino Console (Vercel)
       |
       | queued job
       v
Upstash Redis queue
       ^
       |
       | poll / complete
       |
Aino Browser Worker
       |
       +-- Playwright
       +-- Chromium
       |
       v
AliExpress product page
       |
       +-- mtop.aliexpress.pdp.pc.query
       |       |
       |       +-- skuPaths
       |       +-- skuPriceInfoMap
       |       +-- skuProperties
       |       +-- SHIPPING
       |       +-- PRICE_EXTEND
       |
       +-- rendered page fallback
```

## Structured response extraction

The parser joins variant information by supplier SKU ID:

```text
skuPaths.skuId
      +
skuPriceInfoMap[skuId]
      ↓
Aino variant
```

The resulting variant may contain:

- SKU ID
- variant attributes
- stock
- supplier price
- source path

Shipping observations may contain:

- ship-from country
- shipping amount
- delivery minimum/maximum days
- delivery provider
- warehouse type / solution identifiers when available

Trade observations preserve supplier-stated text such as VAT and import-charge notices. They are evidence, not an Aino customs/tax conclusion.

## Important evidence rule

The worker does not invent missing supplier facts. If the structured response does not contain a mandatory field, the canonical Product Record remains PARTIAL and downstream Selection/Pricing stays blocked.

The raw supplier response is retained on the acquisition job, while the canonical Product Record stores a reference to it. This prevents multi-megabyte supplier payloads from being copied into the frontend product object.
